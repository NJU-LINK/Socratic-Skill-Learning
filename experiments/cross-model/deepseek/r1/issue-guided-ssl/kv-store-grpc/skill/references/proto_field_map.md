# Proto3 field-type mapping table (Python targets)

When authoring `*.proto` for grpc_tools-protobuf-backed Python bindings, map the
desired logical field to proto syntax. Every field carries a unique field
number; order across versions must stay stable (wire compatibility).

| Logical type / shape | Proto syntax | Python attribute after codegen |
|---|---|---|
| string | `string name = 1;` | `str` (proto3 always a `str`, never None) |
| 32-bit signed integer | `int32 n = 1;` | `int`, serialization rejects out-of-range (< -2^31 or > 2^31-1) |
| 64-bit signed integer | `int64 n = 1;` | `int` (Python ints unbounded; wire format varint) |
| unsigned integer | `uint32` / `uint64` | `int`, negative rejected at serialization |
| boolean | `bool ok = 1;` | `bool` |
| float / double | `float x = 1;` / `double x = 1;` | `float` |
| bytes | `bytes b = 1;` | `bytes` |
| enum | `enum Color { COLOR_UNSPECIFIED = 0; COLOR_RED = 1; }` then `Color c = 1;` | int-like enum wrapper; **value 0 is the default and must be a meaningful/unspecified member** (proto3 rule) |
| repeated scalar | `repeated string tags = 1;` | sequence-like container, empty by default |
| map | `map<string, int32> counts = 1;` | dict-like container, empty by default |
| nested message | `message Inner { string s = 1; }` ... `Inner inner = 1;` | message object; proto3 constructs the child (singleton semantics: always present, never None on read) |
| repeated message | `repeated Inner items = 1;` | list of message objects, empty by default |
| oneof | `oneof choice { string a = 1; int32 b = 2; }` | only one field set; `WhichOneof('choice')` |

## Rules that generate silent failures if broken

- **Proto3 has no required fields and no explicit presence for scalars**:
  a missing scalar comes back as its zero value (0, "", False). If a variant
  needs "was this set?" distinction, use `optional` keyword or a message wrapper.
- **Enum member 0 is mandatory** in proto3 and is the default. Never leave the
  first enum member unset in a design that relies on "absent".
- **int32 responses raise at construction/serialization for out-of-range**
  values (`ValueError`). Aggregates (e.g., namespace totals) are bounded by
  2^31-1 unless the proto uses int64.
- **Message-type fields are implicitly present**: reading a nested message
  field returns an instance (default-constructed), so `if msg.inner:` is
  always truthy; check a marker field instead.
- **Naming**: message and field names are case-sensitive and become Python
  attributes verbatim (lowerCamelCase fields stay lowerCamelCase in Python
  bindings generated by grpc_tools — `request.namespace`, NOT snake_case).
